# VNC SDN service: цикл MVP с периодом 1 мс

Сборка и запуск в CODAC Linux из каталога `b-55b2-sdn2ml-sdd`:

```sh
make -C src/main/c++/vnc-sdn-service CODAC_ROOT=/opt/codac
target/bin/vnc-sdn-service
```

Интерфейсы `ens192` и абсолютный путь к XML пока заданы в `vnc-sdn-service.cpp`;
перед запуском проверьте их соответствие стенду.

Период `kPeriodNs = 1000000` задаёт целевую частоту 1 кГц. Один поток ожидает
абсолютный момент по `CLOCK_MONOTONIC`, принимает без ожидания до четырёх пакетов
от каждого IOC, вычисляет сумму и вызывает публикацию один раз для каждого
выходного топика. Ограничение приёма предотвращает бесконечную обработку очереди;
при большой входной нагрузке в очереди могут оставаться старые пакеты.

До первого приёма значения IOC равны нулю. При отсутствии новых пакетов
сохраняются последние значения; контроль их возраста пока не реализован.
Генератор проекта обновляется раз в 100 мс, поэтому публикация с частотой 1 кГц
сама по себе не означает получение новых измерений с такой частотой.

Просроченные периоды пропускаются без догоняющей серии публикаций. Вывод в
консоль и запись в файл внутри цикла отсутствуют. При SIGINT (Ctrl+C) или SIGTERM
печатаются:

- `cycles`: количество выполненных циклов публикации;
- `skipped_periods`: количество пропущенных временных слотов;
- `publish_errors`: количество неуспешных вызовов обёртки публикации;
- `max_wake_lateness_ns`: максимальное опоздание начала цикла относительно расписания;
- `max_work_ns`: максимальное измеренное время приёма, расчёта и публикации.

Это мягкое реальное время: ОС и SDN-вызовы могут задержать цикл. Успешный
`Publish()` не подтверждает доставку. На стенде измеряйте интервалы пакетов и
потери на подписчике под рабочей нагрузкой; приведённые счётчики не заменяют
такую проверку. При ошибках публикации итоговый код завершения равен 1.
